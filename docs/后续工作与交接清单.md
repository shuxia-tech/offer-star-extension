## 阶段一：恢复环境与基础门禁（P0）

电脑维修后由代理执行：

1. 安装 Node.js 20+、Git、Chrome/Edge、Firefox。
2. 克隆仓库并执行 `npm ci`。
3. 执行 `npm run verify`，保存完整输出。
4. 运行 `npm run test:e2e:extension` 和 `npm run test:e2e:ai`。
5. 运行 `npm run test:firefox:runtime`。
6. 重新确认 `npm run test:firefox:fixture`。该命令在 Windows 上的 web-ext 调试端口参数曾需要修正，失败时要修脚本并记录日志，不得跳过。

完成标准：类型检查、全量单测、三浏览器构建、Manifest/契约/密钥检查和真实 Edge E2E 全部有本次环境输出。

## 阶段二：BOSS 直聘真实回归（P0）

需要用户完成：

1. 在 Firefox 中登录 BOSS 直聘。
2. 如果出现验证码、`_security_check` 或安全验证，用户手工完成。
3. 打开真实职位申请表，不要在验证码页面测试。
4. 用户点击悬浮球、扫描页面，再由用户确认后点击填写。

代理记录：脱敏 URL、识别字段数量、成功字段、失败字段、控制台中文日志和是否触发安全边界。禁止记录账号、密码、手机号、邮箱、身份证和完整简历。禁止自动提交职位。

完成标准：至少三个核心字段真实写入；非法值被拒绝；页面变化后旧结果失效；没有自动提交行为。若 BOSS 页面仍处于风控页，结果记录为“安全边界验证通过”，不能记为表单填写通过。

## 阶段三：重点招聘网站真实回归（P1）

按 [登录清单](真实回归登录清单.md) 由用户逐站登录并验证：BOSS 直聘、智联招聘、前程无忧、猎聘、拉勾、牛客、实习僧、应届生以及 Moka/北森 ATS。

每个站点完成：悬浮球、面板、站点识别、至少三个核心字段、用户确认后填写、非法值拒绝、异步变化重新扫描和不自动提交。结果写回 [真实站点回归矩阵](真实站点回归矩阵.md)。

## 阶段四：适配增强（P1）

1. 对真实回归失败字段分类：通用规则、标签推断、异步控件、分步表单、跨域 iframe 或站点风控。
2. 通用问题修复 `src/content/dom-engine.ts` 和 shared 逻辑；站点特殊问题才修改 adapter 或 `site-field-overrides.ts`。
3. 每个修复同时补充脱敏 HTML 夹具、单元测试和相关文档。
4. 为高频站点增加动态下拉、分步表单、照片、附件和重复经历区块夹具。

## 阶段五：网站端生产链路（P1）

在有部署权限和回滚方案后：

1. 在 `offer-star-web` 独立仓库确认服务端 `DEEPSEEK_API_KEY` 等变量，只存服务器环境。
2. 部署 `openLogin=1` 登录弹窗和扩展 AI 代理相关代码。
3. 用线上浏览器冒烟确认登录弹窗、登录态同步和 AI Key 不暴露。
4. 线上检查失败时先回滚网站端，不修改插件端绕过错误。

## 阶段六：稳定性与发布准备（P2）

- 增加 Firefox 临时 profile 的 CI/可重复执行方案。
- 保留开发日志，稳定后根据脱敏指标降低冗余日志。
- 完成权限说明、隐私说明、商店 Manifest 和发布包检查。
- 评估 Chrome、Edge、Firefox 商店各自的审核限制和更新流程。
- 发布前重新执行 `npm run verify:full`，保存版本号、提交号、构建产物校验和回归矩阵。

## 用户需要配合的事项

用户只需要在真实网站相关步骤中完成登录、验证码、人机验证、安全验证、照片/附件/敏感问题确认和最终填写确认。代理不应索要密码、验证码、支付信息或完整简历原文，也不应自动点击最终投递按钮。

## 每项功能的完成标准

功能只有同时具备以下证据才算完成：正常路径测试、异常或安全边界测试、相关单测和构建通过、真实网页证据或明确的用户手工验收、日志脱敏并同步更新文档和站点矩阵。

## 交接后第一条工作建议

恢复电脑后不要直接改业务代码。先运行 P0 环境门禁，确认失败属于环境问题还是代码回归，再从 Firefox 自动夹具和 BOSS 真实回归开始。
