# Offer Star 浏览器插件开发与验收计划

本文档是插件开发阶段的执行基线。网页内悬浮面板是唯一主交互，网页悬浮球和浏览器工具栏图标都会打开同一个面板；Chromium 与 Firefox 都不注册原生 Side Panel 或 Sidebar。

## 一、产品交互基线

1. 用户打开招聘网站的职位详情或申请页面。
2. 内容脚本只在普通 `http`/`https` 页面注入右下角悬浮球，不注入浏览器内部页面、扩展商店和受限制页面。
3. 用户点击悬浮球后，当前网页右侧展开 Offer Star 悬浮面板。面板通过隔离 iframe 加载，绑定当前标签页 ID。
4. 点击“打开 Offer Star 登录”必须通过后台页创建官网标签页，即使官网残留旧 token 也要直接打开登录弹窗；打开失败时必须向面板展示可操作的中文错误，不允许静默无响应。官网登录完成后通过 `storage` 事件和同页状态轮询同步扩展授权，自动刷新简历列表，也提供“刷新登录状态”兜底按钮。
5. 面板头部提供“简历预览”入口，由后台页打开 Offer Star 简历管理页，便于用户在多个简历之间切换或修改内容。
6. 用户点击“扫描当前页面”。插件先识别站点，再扫描普通控件、Shadow DOM、同源 iframe、动态区块和常见自定义下拉框。
7. 扫描完成后，面板头部显示当前站点和“专用适配 / 通用规则”状态，用户可以先确认识别结果再继续。
8. 面板用“扫描页面 → 确认字段 → 完成填写”三步进度条表达当前阶段；高置信度字段进入可填写列表，低置信度字段、敏感字段、协议授权、照片和附件进入待确认列表。
9. 扫描后显示当前页面标题和去除查询参数的站点地址，帮助用户确认标签页上下文，同时不把可能包含个人信息的查询参数展示在面板中。
10. 用户确认后才写入页面。插件不会自动点击“提交”“投递”“立即申请”等最终动作。
11. 面板关闭只移除当前网页面板；页面导航或表单结构变化会使旧扫描结果失效，要求重新扫描。

## 二、阶段拆解

### 阶段一：通用表单与网页内面板

- 完成 WXT 多浏览器构建：Chrome、Edge、Firefox。
- 完成网页悬浮球、悬浮 iframe 面板、关闭和导航清理。
- 支持文本框、文本域、原生下拉框、日期控件、复选框安全边界和文件控件。
- 悬浮面板使用自定义拖拽上传卡片，支持点击、键盘 Enter/Space 和拖拽三种入口；文件仍需用户确认后才写入页面。
- 面板操作图标使用内嵌 SVG，不依赖浏览器字体或外部图标资源，保证 Chrome、Edge、Firefox 的视觉一致性。
- 建立脱敏日志、失败原因和撤销填写能力。

完成证据：本机最终验收执行 `npm run verify:full`；它包含 `npm run verify`、扩展 E2E、AI E2E、Firefox runtime 和 fixture。`npm run verify:local` 只运行插件本地门禁，`verify` 还需要真实的 Web / Node 字段契约；不能把本地门禁通过当作发布通过。Mac 操作和当前阻断见 [Mac 测试指南](Mac测试指南.md)。

### 阶段二：主流招聘网站适配

- 站点适配器只负责域名、路径和职位上下文选择器。
- 字段识别和填写优先复用通用引擎，只有站点特殊控件才增加专用逻辑。
- 当前共有 65 个非 `generic` adapter，覆盖 BOSS 直聘、智联招聘、前程无忧、猎聘、拉勾、牛客、实习僧、应届生、国家大学生就业服务平台、公共招聘平台、汇博招聘、看准网、鱼泡网、斗米、伯乐在线、兼职猫、百姓网招聘、主要互联网企业校招站点和 Moka/北森等 ATS。
- 每新增一个非 `generic` adapter，必须同时新增至少一个 HTML 表单夹具和识别测试。

完成证据：`tests/site-form-fixtures.test.ts` 的声明与夹具集合相等，不能只增加 adapter 不增加夹具。

### 阶段三：AI 辅助映射与草稿

- AI 只接收脱敏后的页面字段、职位描述和必要的简历摘要。
- 面板和后台实际出站边界均执行脱敏：去除 URL 凭证、查询参数、片段，以及文本中的常见手机号、邮箱和身份证号；内部导航仍使用原始 URL，查询参数变化必须使旧结果失效。
- DeepSeek Key 只保存在 `offer-star-web` 服务端环境变量，扩展不保存、不下发。
- AI 输出必须经过结构化校验和页面版本校验。
- 低置信度映射不得自动填写；AI 生成的自我介绍、项目描述等草稿必须由用户确认。
- 网络超时、5xx 和无效 JSON 需要显示可操作的中文错误，并允许重新扫描或重试。

完成证据：AI 请求重试、超时、结构化解析、过期结果和低置信度过滤测试全部通过。

### 阶段四：真实站点回归与稳定性

- 为每个重点站点准备可重复的脱敏 HTML 夹具。
- 每个重点站点至少验证：识别、扫描、核心字段填写、非法值拒绝、动态控件或多步骤行为中的一项。
- 对登录限制、验证码、跨域 iframe 和站点改版记录为适配限制，不绕过网站安全机制。
- 稳定后再降低冗余日志级别；开发阶段保留中文 `console.info`、`console.warn` 和 `console.error`。

## 三、测试分层

### 单元测试

验证纯逻辑和 DOM 引擎：字段匹配、值校验、日期转换、站点识别、AI 映射、缓存、页面版本、附件路由、Shadow DOM、iframe 和动态区块。

### 夹具测试

使用脱敏 HTML 模拟招聘网站，不访问真实用户账号。每个站点夹具至少断言：

- URL 被正确识别为目标 adapter。
- 至少识别三个核心字段。
- 至少有一个值真实写入页面。
- 夹具不会意外回退到 `generic`。

### 真实浏览器 E2E

使用 Playwright 启动 Edge 或 Chrome 扩展，验证：

- 悬浮球注入和刷新去重。
- 工具栏触发消息打开同一个网页内悬浮面板。
- 面板头部“简历预览”会打开带 `target=resume_assistant` 的官网简历管理页。
- 网页内 iframe 面板实际加载。
- 面板显示三步填写进度，并随扫描、确认和填写阶段更新当前步骤。
- 扫描后显示页面标题和脱敏地址，地址保留端口但不显示查询参数或 hash。
- 面板头部和主体在桌面窄窗口及 320px 小屏宽度下不得横向溢出；响应式网格和标题单行布局由真实扩展 E2E 验证。
- 未登录时点击“打开 Offer Star 登录”能创建官网标签页，失败时面板显示中文错误；`offer-star-web` 的登录参数单测和本地浏览器冒烟验证确认带 `openLogin=1` 的官网地址能直接打开登录弹窗。
- 登录 token 被清除后，面板必须清空旧简历、当前简历选择和 AI 草稿，并恢复登录入口；该路径由真实扩展 E2E 覆盖。
- 登录态下打开简历选择器、切换到另一份简历并使用新简历数据填写页面；该路径由真实扩展 E2E 覆盖。
- 面板扫描当前页面并显示识别结果。
- 当页面存在未识别字段时，面板必须进入“确认字段”审核卡；真实扩展 E2E 会动态加入未知字段，验证“仅填写新增内容 / 全部覆盖重填”切换、选中状态和后续确认入口。
- 检测到 `_security_check`、验证码或明确的异常访问文案时，扫描必须停止并提示用户先完成网站安全验证；安全验证页不得进入一键填写流程，单测和真实扩展 E2E 均覆盖。
- 用户选择的填写模式在关闭并重新打开悬浮面板后必须保持；真实扩展 E2E 会重新扫描待确认字段并验证覆盖模式仍被选中。
- 高置信度字段的一键填写、撤销本次填写和表单恢复由同一条真实扩展 E2E 闭环验证。
- 面板关闭后 DOM 节点被移除。
- 合法值填写和非法值拒绝。
- AI 面板按钮和草稿审核逻辑由扩展共享状态单测、Web 代理成功响应测试和 Node 结构化响应测试覆盖；真实浏览器 AI 成功路径必须连接可用的测试网关，不能用无法拦截扩展 Service Worker 的页面网络桩冒充通过。
- `npm run test:e2e:ai` 使用本地脱敏 mock 网关和临时构建配置，真实验证扩展 Service Worker 请求、AI 草稿展示、编辑和拒绝；脚本结束后自动恢复生产 Chrome 构建。
- AI 请求期间按钮必须显示“AI 分析中…”并禁用重复操作，真实 AI E2E 会校验进行中状态，响应结束后再恢复可操作状态。
- 照片、简历附件按 `accept` 分配。
- 面板内拖拽上传卡片可以选择文件并显示待确认附件预览。
- 页面异步变化后旧结果失效。
- 未登录时重复登录轮询不得覆盖表单过期或安全提示；已登录授权消失时仍必须清理旧简历。

### Firefox 验收

- `npm run test:firefox`：构建、Manifest 清理和 `web-ext lint`。
- `npm run test:firefox:runtime`：确认 Firefox 可以接受临时扩展并完成安装。
- `npm run test:firefox:page`：连接用户明确提供的 Firefox 调试端口，只读检查真实招聘标签页上的悬浮球注入和安全验证状态；不执行点击、填写或提交。
- `npm run test:firefox:fixture`：自动构建扩展、启动 Vite 脱敏测试页和 Firefox 临时 profile，再通过 Firefox 调试协议只读检查悬浮球与表单控件；命令结束会清理本次启动的进程。
- fixture 使用 web-ext 分配的真实调试端口，不重复添加 `-start-debugger-server` 参数。Firefox 的系统安装路径和 Playwright 测试浏览器自动识别，也可以通过 `FIREFOX_EXECUTABLE_PATH` 显式指定。
- Firefox 临时 profile 的脱敏表单可以通过 `FIREFOX_SMOKE_HOST` 和 `FIREFOX_SMOKE_SELECTORS` 检查悬浮球与关键控件同时存在，作为真实 Firefox DOM 运行时证据；该检查仍然只读，不代替用户授权的真实招聘站点填写验收。
- 手工加载 `.output/firefox-mv2/manifest.json` 后，验证悬浮球、网页内面板和工具栏入口。

## 四、功能完成标准

一个功能只有同时满足以下条件才算完成：

1. 有中文注释、中文日志和清晰的异常处理。
2. 有正常路径测试。
3. 有至少一个失败、安全边界或异常路径测试。
4. 影响真实页面时，有真实浏览器 E2E 或 Firefox 手工验收证据。
5. `npm run typecheck`、全量单元测试、三浏览器构建和 Manifest 检查通过。
6. 新增站点时，适配器、夹具、识别测试和文档同步更新。
7. 日志不得包含 token、API Key、手机号、邮箱、身份证号或完整简历原文。

## 五、开发期问题定位顺序

1. 先看浏览器控制台中的 `[Offer Star][Content]`、`[Offer Star][Background]` 和 `[Offer Star][FloatingPanel]` 日志。
2. 记录浏览器、站点、去除查询参数后的 URL、扫描字段数量、失败字段和失败原因。
3. 重新扫描确认是否为页面版本过期。
4. 使用脱敏 HTML 夹具复现，再修改站点 adapter 或通用引擎。
5. 修改后先跑相关测试，再跑 `npm run verify` 和真实浏览器 E2E。
